# Static hosting comparison

Reviewed 2026-11-10 against official documentation. Recommendation only: no account, resource, preview, or production deployment has been created. Free limits can change; recheck at account setup. No custom domain, paid plan, or backend is needed for this release.

## Recommendation

Use **Cloudflare Workers Static Assets**, with assets only and a provider `workers.dev` HTTPS URL. This is a judgment for this repository: a small assets configuration preserves the existing Vite output, static requests are free/unlimited, and the platform has Git builds, previews, and version rollback. It also leaves an optional path to server-side room coordination later, without adding any multiplayer code now. [Static billing](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/), [Git builds](https://developers.cloudflare.com/workers/ci-cd/builds/), [rollback](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/).

Cloudflare Pages is a close alternative if its familiar static-site dashboard is preferred. Vercel Hobby has convenient Vite setup but personal/non-commercial restrictions and narrower free rollback. GitHub Pages avoids a separate hosting account for a public repository, but adds project-subpath handling and lacks a comparable built-in per-PR preview workflow. None is a reason to redesign the game.

## Trade-offs and unresolved external checks

Workers adds a deployment CLI/configuration compared with Pages' build/output form. Wrangler is not installed yet; the checked-in example is not an account binding or an executed deployment. A clean static-only project needs no Worker handler, SSR adapter, Vite plugin, database, secret, or extra production dependency. See [routing/configuration](https://developers.cloudflare.com/workers/static-assets/) and the [deployment plan](deployment-plan.md).

Native Git auto-deployment does not prove our separate GitHub verification passed. Do not enable automatic production promotion on push. Public previews are also publications requiring authorization. Provider account/repository integration, available names, retention, actual HTTPS, and rollback must be verified after provider approval; local Vite preview cannot establish them. GitHub Pages eligibility depends on actual repository visibility/account plan, which has not been queried or changed.

Frontend hosting remains replaceable. Future multiplayer would require a separately approved server-authoritative session and player-visible protocol on every provider; a static host alone does not prevent hidden-state inspection or cheating. That work is not part of this release.
